## 📊 Сравнение архитектур

### Старая архитектура (subprocess)
```
[Python Bot] → [subprocess] → [New Node.js Process]
                            → [Another Node.js Process]
                            → [Another Node.js Process]
                            → ...
```

**Проблемы:**
- Каждый запрос создает новый процесс
- Высокие накладные расходы (~500ms на запрос)
- Огромное потребление памяти (~50MB на процесс)
- Максимум ~50 одновременных пользователей

### Новая архитектура (HTTP API)
```
[Python Bot] → [HTTP Request] → [Single Node.js API Server]
            → [HTTP Request] ↗
            → [HTTP Request] ↗
            → ...
```

**Преимущества:**
- Один процесс обрабатывает все запросы
- Низкие накладные расходы (~10ms на запрос)
- Минимальное потребление памяти (~0.5MB на запрос)
- Масштабируется до 1000+ пользователей

## 🎯 Миграция существующего кода

### Было (subprocess):
```python
from spark_withdrawal import SparkWithdrawalManager

manager = SparkWithdrawalManager()

# Синхронный вызов
result = manager.create_lightning_invoice(mnemonic, 1000)
```

### Стало (HTTP API):
```python
from spark_withdrawal_v2 import SparkWithdrawalManager

manager = SparkWithdrawalManager()

# Асинхронный вызов
result = await manager.create_lightning_invoice(mnemonic, 1000)
```

**Изменения:**
1. Импорт из `spark_withdrawal_v2` вместо `spark_withdrawal`
2. Добавить `await` перед вызовом метода
3. Функция должна быть `async def`

## 🚀 Production готовность

### Для production окружения:

1. **Используйте PM2** для автозапуска:
```powershell
npm install -g pm2
cd nodejs
pm2 start api_server.js --name spark-api -i 4
pm2 startup
pm2 save
```

2. **Настройте мониторинг**:
```powershell
pm2 logs spark-api       # Логи
pm2 monit                # Мониторинг в реальном времени
pm2 status               # Статус процессов
```

3. **Масштабируйте** при необходимости:
```powershell
pm2 scale spark-api 8    # Увеличить до 8 процессов
```
